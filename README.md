# Banking77 — классификация банковских обращений

Проект по многоклассовой классификации текстовых обращений клиентов банка. Модели обучены распознавать **77 типов запросов** из датасета Banking77. Проведены эксперименты с NLP-моделями. Также реализован локальный сервис для инференса: **FastAPI + DistilBERT + PostgreSQL**. Запускается с помощью **Docker Compose**.

## Задача

Датасет banking77 состоит из набора текстовых запросов в службу поддержки банка. Каждый запрос имеет одну из 77 меток - намерение запроса. Именно эту метку необходимо научиться предсказывать. Имеем датасет train, содержащий 10 003 записей, и test, содержащий 3 080 записей. В датасете 77 классов, поэтому для оценки качества использовались **Macro F1** и **Accuracy**.

## Модели и результаты

Сравнивались классический подход TF-IDF + Logistic Regression и модели семейства BERT.

| Модель | Test Macro F1 | Test Accuracy | Медианное время инференса на CPU |
|---|---:|---:|---:|
| TF-IDF + Logistic Regression | 0.9096 | 0.9097 | 2.99 мс |
| DistilBERT | **0.9298** | **0.9299** | 32.05 мс |
| BERT-base | — | — | 61.93 мс |


**Для API выбрана модель DistilBERT.** Т.к. она показала более высокое качество, чем TF-IDF + Logistic Regression, и работала быстрее BERT-base в проведённых измерениях. TF-IDF остаётся полезным быстрым baseline.

В экспериментах использовались символьные TF-IDF n-граммы и Logistic Regression, а для трансформеров дообучение на размеченных обращениях с подбором learning rate и выбором лучшей модели по качеству на валидации. Тестовая выборка использовалась для финальной оценки.

## Как работает сервис

```text
Пользователь → POST /predict → FastAPI → DistilBERT → предсказанный класс
                                  │
                                  └→ PostgreSQL (история запросов)
```

При запросе API:
1. Получает JSON с полем `text`.
2. Токенизирует текст и вычисляет предсказание DistilBERT.
3. Измеряет время инференса в миллисекундах.
4. Записывает текст, предсказанный класс и время инференса в таблицу PostgreSQL.
5. Возвращает предсказанный класс в JSON.

Если запись в PostgreSQL завершилась ошибкой Psycopg, сервис записывает исключение в лог и всё равно возвращает предсказание.

## Локальный запуск через Docker Compose

Нужны Docker Engine и Docker Compose. Для скачивания весов модели также потребуется Git LFS.

1. Клонируйте репозиторий и перейдите в его папку.
2. Создайте локальный файл настроек из примера:

   ```bash
   cp .env.example .env
   ```

3. В `.env` укажите собственные значения `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_PORT`. При локальном запуске вне Docker используется `DB_HOST=localhost`; внутри Compose для API адрес базы переопределяется как `DB_HOST=db`.
4. Запустите сервисы:

   ```bash
   docker compose up -d --build
   ```

5. Откройте **http://127.0.0.1:8000/docs** и отправьте запрос через `POST /predict`.

При первом запуске с пустым томом PostgreSQL выполняет `sql/init.sql` и создаёт таблицу `predictions`. Данные сохраняются в именованном Docker-томе между перезапусками контейнеров.

## База данных и аналитика

Таблица `predictions` содержит:

| Поле | Назначение |
|---|---|
| `id` | Уникальный ID запроса |
| `text` | Текст обращения |
| `predicted_class` | Предсказанный класс |
| `created_at` | Время записи |
| `inference_time_ms` | Время инференса на CPU, мс |

В `sql/analytics.sql` находятся запросы для анализа количества обращений, распределения по категориям, времени инференса, динамики обращений по дням и зависимости времени инференса от длины текста.

Запустить весь аналитический SQL-файл из корня проекта:

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < sql/analytics.sql
```

При работе с небольшим числом тестовых запросов результаты аналитики иллюстративны и не описывают реальную нагрузку.
